# Kopuz integration

**Date:** 2026-11-03
**Status:** planned, on `main`
**Spec:** `docs/superpowers/specs/2026-11-03-kopuz.md` (wins on conflict)

Each task is one subagent, run in order, ending in its own commit pushed to
`origin/main` with the verification output read.

## Task 1: `crates/fs-kopuz`, the wire

- New workspace crate, no dependency outside what the workspace already
  carries (`serde_json` at most). Modules: `pb` (varint, tags, a small
  `Reader`/`Writer`), `h2` (frames, HPACK literal encoding, a blocking-free
  connection type generic over `AsyncRead + AsyncWrite` from `futures-lite`,
  which the shell already uses), `api` (typed requests and decoded replies for
  `GetPlayerState`, `Subscribe`, `GetLyrics`, `GetFavorites`, `SetFavorite`,
  `Rate`, `DontRecommend`), `socket_path()`.
- Tests: codec round trips and fixed byte vectors for every message the crate
  writes or reads; one frame exchange against an in-test `h2` server
  (dev-dependency) proving a unary call, a server stream past 65535 bytes (the
  window update), and a GOAWAY ending the call as an error.
- Add it to `dev/lint.sh`'s pure-crate tests and to `dev/smoke-map.toml`
  (runs nothing for this task).
- Verify: `just cargo test -p fs-kopuz`, `just lint`.

## Task 2: the service and lyrics

- `services/kopuz.rs`: connects while the active MPRIS player's bus name is
  `org.mpris.MediaPlayer2.kopuz` or `...kopuz.instance<pid>` (fs-mpris has to
  expose the bus name if it does not already) and the socket exists; follows
  `Subscribe`, keeps `{connected, key, title, artist, favorite, actions}` in
  the store; reconnects with backoff while the player exists, drops when it
  goes. Title and artist must match MPRIS's before anything is published.
- `services/lyrics.rs`: when the ask's player is Kopuz and the store has its
  key, `GetLyrics` first; synced lines win, cached with source `kopuz`; an
  empty or failed answer falls through to the web chain unchanged.
- `media status` gains the `kopuz` block; `ipc-golden.jsonl` updated.
- Verify: `just lint`, `just smoke-affected`.

## Task 3: like and the actions

- Read Kopuz's own controls (`kopuz/crates/components/src/playback/controls.rs`,
  `kopuz/crates/hooks/src/favorites.rs`) and offer exactly the actions it
  offers for the playing track.
- IPC `media like [toggle|on|off]`, `media dislike`, unknown args an error
  string; golden lines added.
- Media panel: a heart (Lucide `heart`, filled when liked) and the dislike
  action in the transport row, only while `kopuz.connected`; keyboard
  reachable through the panel's row navigation; panel-language check holds.
- Verify: `just lint`, `just smoke-affected`.

## Task 4: a smoke leg

- `dev/smoke.d/kopuz.sh` `--kopuz`: a stub `kopuzd` on the session's
  `$XDG_RUNTIME_DIR/kopuz/kopuzd.sock` (Python, hand-rolled h2 like the
  crate, or the crate's own test server built as a dev binary; no grpcio on
  the rig) plus a real mpv owning `org.mpris.MediaPlayer2.kopuz` through
  mpv-mpris's name (or a Gio stub): lyrics from the stub drawn with
  `media lyrics` source `kopuz`, `media like toggle` reaching the stub as
  `SetFavorite{key, true}` and the heart filled in the photographed panel, a
  daemon-pushed favourite change repainting it, the stub killed leaving no
  heart and the web chain answering. Map the leg in `dev/smoke-map.toml`
  and document it in CLAUDE.md's leg list.
- Verify: `just smoke --kopuz` at both scales, read the PNGs.
