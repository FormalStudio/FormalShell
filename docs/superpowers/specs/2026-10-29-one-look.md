# One look, configured

Owner, 2026-10-29 (`Plan.md`, decisions 1, 2, 5, 7, 8, 9, 11, 12 and
phase 1): one look, named FormalShell, and what the four presets did
becomes configuration. This wins over `2026-09-18-theme-boundary.md`,
`2026-08-25-shadcn-omarchy-redesign.md` and
`2026-09-17-pantheon-mode-declarative-themes.md` where they disagree. The
boundary spec's bar edge and paint, frame, card arrival, icon set and font
families leave the table for settings or become fixed; the 08-25 chrome
numbers (radius 10, opacity 0.85, the strip, the row toast) retire; the
09-17 mechanism (declarative JSON by role and state, every role declared)
stays over one table. Nothing aliases an old key: a removed key is ignored
and logged once per start as `settings: <key> is no longer read`.

## 1. Settings

### The new keys

| key | values | default | replaces |
| --- | --- | --- | --- |
| `layout` | `bar`, `sidebar` | `bar` | nothing (new) |
| `bar.position` | `top`, `bottom`, `left`, `right` | `top` | itself, unchanged |
| `bar.style` | `transparent`, `solid`, `corners` | `transparent` | the `bar` and `paint` habits, `bar.paint` |
| `motion.morph` | `true`, `false` | `true` | the `emerge` habit |
| `render.backend` | `auto`, `gpu`, `cpu` | `auto` | nothing (reserved) |

An unknown value reads as the default, the rule `barpaint::pin` already
follows (`crates/fs-theme/src/barpaint.rs:248`). A non-boolean
`motion.morph` is malformed and reads as `true`, as `presets::boolean` does
today (`crates/fs-theme/src/presets.rs:108`).

**`layout`.** Phase 1 parses it and reports it in `debug dump`'s `theme`
block as `layout`; `sidebar` logs `layout: sidebar is not built yet` once
and draws the bar. The placement rule is fixed now so phase 3 does not
reopen it: the sidebar takes `bar.position` when that is `left` or
`right`, and the left edge under `top` or `bottom`.

**`bar.style`.** One band renderer, wingpanel's (`surfaces/bar/mod.rs:417`);
the strip and the `wingpanel` flag (`bar/mod.rs:58`) go.

- `transparent`: today's `Pin::Transparent` (Pantheon's `paint` habit):
  wingpanel's rule without the busy branch, per-cell ink (`bar_ink`), the
  `maximized` paint under a fullscreen window.
- `solid`: always the `maximized` paint (black at 1, light ink, the 1px
  `BORDERS` edge), GNOME Shell's panel and wingpanel's own fallback. The
  `services/barpaint.rs` reading starts only under `transparent` (the gate
  at `wayland.rs:701` reads the key instead of `bar.wingpanel()`).
- `corners`: `solid` plus a concave fillet of radius `frame.radius` at each
  end of the band's inner edge, in the band's fill, on the bar's own
  surface: no new layer, the exclusive zone unchanged, the far screen
  corners undrawn.

`bar.paint` and its seven pins are removed. `barpaint::Pin` keeps
`Transparent` and `Paint(Maximized)` as the two internal answers;
`PINS`, `Pin::Auto` and `pin()` go. `bar paint`'s `pin` and `pinned` fields
become `style`.

**The frame.** `frame.thickness` (default 0) and `frame.radius` stay and are
read directly; the `frame` habit and the `frame_habit` gate
(`crates/fs-theme/src/theme.rs:219`) go, so a non-zero thickness draws the
ring under the one table. The ring wears the band's paint (`bar/mod.rs:429`,
role `frame`). `frame.radius` defaults to 15 (libadwaita's window radius,
`src/stylesheet/_common.scss:17`) instead of "20 when `theme.radius` is
positive". With a ring drawn, `corners` adds nothing: the ring's own
fillets are the corners.

**`motion.morph`.** `true` is today's `join` emerge: cards bud off the bar's
inner edge and morph between sizes (`surfaces/card.rs`, `motion.rs`).
`false` is Pantheon's `popover`: the card drops from its cell with its own
cast. The `slide` emerge goes with cartridge. Under `bar.style:
transparent` there is no line to open a gap in, so the join draws the
card's shoulders against the band's inner edge and leaves the band alone;
under `solid` and `corners` the band's `BORDERS` edge is the line and the
gap opens in it as the strip's did. `card.rs:68` reads the key, and the
block at `card.rs:73` that resolves a second Theme by preset name to
borrow Pantheon's casts goes (there is one table to read them from).

**`render.backend`.** Reserved. Phase 1 parses it and reports `render:
{"asked": <value>, "backend": "cpu"}` in `debug dump`; every value draws
with `vello_cpu`. Phase 6 gives `auto` and `gpu` meaning.

## 2. The table

`crates/fs-theme/themes/pantheon.json` becomes `crates/fs-theme/formalshell.json`,
read through one `fs_theme::table()`; `tables.rs` and `presets.rs` go and
`Theme::resolve` (`theme.rs:205`) reads the surviving keys itself. The
material stays elementary's and lightly skeuomorphic: the `HIGHLIGHT` lit
rim and `FACE` gradient on raised controls, `INSET` on fields and troughs,
the `SHADOW_*` ladder on cards, black `BORDERS`. What moves toward GNOME
HIG is the geometry: radii, sizes, spacing, type. Values below are read
off libadwaita's `main` stylesheet on 2026-10-29 (`src/stylesheet/`, file
named beside each).

## 5. Performance baseline

Taken in task 1.0, before any phase 1 code, on `main` as phase 0 left it. Host: g815, natively in a slot (`dev/remote.sh`), the shell built
there with cargo. Each leg runs three times plain and three times under
`FS_CPU_QUOTA=10% FS_CPU_QUOTA_PERIOD=2ms`, the stand-in for e1504g in
power saver. The numbers, from each leg's own output:

| number | leg | source |
| --- | --- | --- |
| cold start, launch to the bar's first commit (ms) | `--idle` | `SMOKE_IDLE` |
| CPU ticks over 60s undriven, all threads | `--idle` | `SMOKE_IDLE` |
| voluntary switches over the same 60s | `--idle` | `SMOKE_IDLE` |
| commits over the same 60s, the clock's excluded | `--idle` | `SMOKE_IDLE_LOG` |
| idle CPU and spinner CPU, % of one core | `--r0-measure 60` | `SMOKE_R0_RESULTS` |
| VmRSS and thread count at 60s | `--r0-measure 60` | `SMOKE_R0_RESULTS` |
| launcher first frame and longest bar gap (ms) | `--r0-measure 60` | `SMOKE_R0_RESULTS` |
| toggle to first launcher commit, p50 and max (ms) | `--menu-budget` | `SMOKE_MENU_BUDGET` |
| GPU at idle: DRM fds the shell holds, `drm-engine-*` time over the 60s | `--idle` | `/proc/<pid>/fd`, `/proc/<pid>/fdinfo` |

The GPU row is new to `idle.sh` (task 1.0 adds it). It is 0 and 0 by
construction while everything draws on the CPU, and it is the number
phase 6 is gated on. The results land in `docs/perf/baseline.json`
(commit, host, quota, the three runs and their median per number).

**The gate.** A phase 1 task lands only when, for every number, the
median of three runs is at or under the baseline median plus the
baseline's own spread (max minus min over its three runs); RSS may rise 2 MB at
most; the idle commit count, the DRM fd count and the engine time stay
exactly 0. Tasks 1.3c and 1.4c run the gate; 1.2 runs `--idle` alone. A
number over the gate is stated in the commit message and the change is cut
or made opt-in (decision 7). Phase 1 deletes code, so a rise is a bug to
find, not a cost to accept.
