# Mac apps in the shell

Atoll (FormalStudio/atoll) runs Mac apps as ordinary Wayland windows. A Mac
app expects three things the shell does not have: a menu bar holding its
menus, a dock holding its icon, badge and dock menu, and a launcher that
knows what it is. This spec adds them.

The owner works from the keyboard. macOS is driven by the pointer, so its
chrome is too. Two rules follow, and they win over everything below:

1. **Pointer chrome is for Mac apps only.** The menu bar exists only while a
   Mac app has focus. The dock exists only while a Mac app runs (section 4).
   A session with no Mac app open has neither, and nothing a native app does
   today changes.
2. **Nothing needs the pointer.** Every menu item and every dock action is
   reachable from the launcher (section 5).

A window is a Mac app's when Hyprland reports its `xdgTag` as `atoll`, or
when its desktop entry carries `X-Atoll-BundleId` (an Electron app atoll
installed draws its own windows and has no tag). `fs_types::Window` gains
`mac: bool` from the first; the entry scan gains the second.

## 1. Transport

Both transports are existing desktop standards, so atoll implements nothing
private to this shell and another shell can read the same exports.

| What | Standard | Who serves |
| --- | --- | --- |
| The app's main menu | `com.canonical.dbusmenu` at an object path the app names | atoll |
| Which menu belongs to which app | `com.canonical.AppMenu.Registrar` (`RegisterWindow`, `UnregisterWindow`, `GetMenuForWindow`) at `/com/canonical/AppMenu/Registrar`, on the bus name `org.atoll.AppMenu.Registrar` | the shell |
| Badge, progress, attention | `com.canonical.Unity.LauncherEntry` `Update(uri, a{sv})`: `count`, `count-visible`, `progress`, `progress-visible`, `urgent` | atoll signals, the shell already listens (`services/activity.rs`) |
| The dock menu | `com.canonical.dbusmenu` at `/org/atoll/DockMenu` on the connection that registered the main menu; the LauncherEntry's `quicklist` names the same path | atoll |

The registrar keeps the standard interface and path but not the standard
bus name. Qt and GTK apps hide their in-window menu bars as soon as
`com.canonical.AppMenu.Registrar` has an owner, which would take a menu bar
away from native apps and give them nothing back (rule 1), so the shell
owns `org.atoll.AppMenu.Registrar` instead and only atoll calls it.

The registrar's window id is an X11 id, which a Wayland window does not
have. The shell therefore keys a registration by the caller's process: it
asks the bus for the sender's pid and matches that against the focused
window's pid. Atoll is one process per app and a Mac app has one main menu,
so the match is exact. The id is kept only to pair `RegisterWindow` with
`UnregisterWindow`; atoll sends 0. A registration from a process whose
windows are not Mac windows is stored and never shown (rule 1).

The KDE appmenu Wayland protocol was the other candidate. It needs the
compositor to carry it, Hyprland does not, and the shell is not the
compositor.

dbusmenu properties the shell reads beyond what the tray reads today:
`shortcut` (`aas`, for example `[["Control","Shift","S"]]`), and the
vendor keys `x-atoll-section` (a heading row) and `x-atoll-badge` (the dock
badge when it is not a number). Unknown keys are ignored by other hosts.

`AboutToShow(id)` is where atoll validates a menu (`menuNeedsUpdate:`,
`validateMenuItem:`), so the shell calls it before it shows or searches a
menu and reads the layout after.

## 3. The menu bar

Present only while the held-focus window is a Mac window whose process
registered a menu. Otherwise the cell is not on the strip and the card is
not in the column.

**Strip (`layout: "bar"`).** `appMenu` is a builtin, in the default left
region between `workspaces` and `activeWindow`. It draws the top-level
titles in the label style, each a hit target with the cell hover wash, the
open one carrying the open mark. The first title is the app's name in
semibold (the application menu), as on the Mac. While a menu is held the
`activeWindow` cell after it is the window's title alone, and nothing when
that title is the app's name again, so the name is on the strip once. On a
vertical strip the titles do not fit: the cell is one `menu` icon and opens
the whole menu in a card, each title a submenu of it.

**Column (`layout: "sidebar"`, the owner's layout).** A Menu card under the
time card: one row per top-level title, the app's name first in semibold,
the way NeXTSTEP stacked an app's menu at the screen's corner. Collapsed to
the rail it is one `menu` icon under the time card and opens the whole
menu.

**An open menu** is the tray's menu card: `Role::Menu`, joined to the bar's
line under (or beside) its title, the same emerge and the same rows.
Additions: a shortcut column in keycaps at the trailing edge and heading
rows. Submenus expand inline, indented, as the tray's do. Disabled rows
take the meta ink and no hover. A click sends dbusmenu `Event(id,
"clicked")` and closes the card; atoll performs the item on the app's main
thread.

The card is the pointer's. It takes no keyboard focus, so the app keeps
its key window and stays the active app while its menu is up, which is
what its validation and its nil-targeted actions (`copy:`, `save:`) need.
The pointer moving onto another title while a menu is open switches menus
with no click, as on the Mac; a click on the open menu's own title or
anywhere off the card shuts it. The keyboard's way to a menu command is the
launcher (section 5).

Updates arrive as `LayoutUpdated` and `ItemsPropertiesUpdated`; the open
card patches in place.

The menu held is the focused window's process's and no other's: the store
drops it on the compositor's own change of focus, ahead of the reader that
follows the focus, so the titles never stand over another app's window. A
call to an app waits three seconds for its answer; the reader takes one
app at a time, and an app that has stopped answering would otherwise hold
every menu after it.

IPC: `appmenu status` (the focused app's pid, its titles with their boxes
on the strip, the open menu and its rows' boxes, whether the session is in
the `mac` submap, and `macBinds`, how many binds the include had recorded
when the submap was last built), `appmenu items <path>` (the items under a title or a
submenu), `appmenu open <title>`, `appmenu close`, `appmenu activate
<path>` (`"File/Export/PDF"`, for a keybind) and `appmenu run <id>` (a
dbusmenu id, what a launcher row calls).

## 4. The dock

`dock.show`: `"mac"` (default), `"always"`, `"never"`.

Under `"mac"` the dock's surfaces exist only while at least one Mac app has
a window. With none there is no surface and no hot edge. `"always"` is for
a pointer user who wants it for every app: it exists while anything is
pinned or open. Recommended default `"mac"` over opt-in: a Mac app that
sets a badge or asks for attention has nowhere else to show it, and the
dock costs a native-only session nothing.

It never takes space. A one pixel transparent strip (`formalshell:dock`,
`Layer::Top`, no exclusive zone) lies along the bottom edge of the output
the live bar is on, or along the top edge where the bar has the bottom,
clear of the hot corners at its ends and of a bar down either side. The
pointer resting on it for `dock.dwell` (150 ms), or a click on it, brings
the dock out. It goes 400 ms after the pointer left it, at once when
another window takes focus with the pointer off it, and stays while its
own menu is up or `dock open` holds it. Under a fullscreen window the strip
is gone (`fullscreen.hideChrome`).

The dock is one card (`Role::Card`, the table's fill, border and radius),
centred, a `barMargin` off the edge's line, coming out of that line and
going back into it as every card does. It takes no keyboard. Icons are 48,
9 apart. No magnification.

Contents, left to right: pinned apps (state.json `dockPins`), a rule, then
open apps that are not pinned, in the order the compositor lists their
first window. An app goes by its desktop entry's id where the icon probe
finds one, else by its window's app id, which for a Mac app is its bundle
id and what its LauncherEntry names. While it is shown it holds native
apps too, so the pointer can reach everything from one place.

| Mark | Source |
| --- | --- |
| Icon | the desktop entry's (`store.appicon`), else the `app-window` glyph |
| Running dot under the icon, brighter on the focused app | the app has a window |
| Badge, top right | `Activity::badges()`: `x-atoll-badge` text, else a count above 0 |
| Progress bar across the icon's foot | the app's running LauncherEntry item |
| Hops | `urgent` on the LauncherEntry or Hyprland's urgent flag: three hops, each lower, again every 4 s while it lasts. With motion off the icon stays put and its dot takes the warning ink. An app turning urgent brings the dock out for 1.6 s. |
| Launching | the Activity launch item: the icon breathes until its window maps |

Click: focus the app's next window after the focused one, or launch it
(`launch::open`). Middle click: another instance. Right click: the menu
card above the icon holding, each group under a rule, the app's own dock
menu, its windows with a tick on the focused one, New Window and its
desktop entry's actions, Keep in Dock or Remove from Dock, and Quit.

The app's own dock menu is the dbusmenu at `/org/atoll/DockMenu` on the
connection that registered its main menu (the path its LauncherEntry's
`quicklist` names), asked for when the card opens and landing in the open
card. Only a Mac app has one.

Quit sends dbusmenu `Event` on the app menu's Quit item (the item with the
SUPER + Q equivalent, else the one whose label starts with Quit) when the
app registered a menu, so `applicationShouldTerminate:` runs; else it
closes each window.

IPC: `dock status`, `dock open`, `dock close`, `dock pin <id>`,
`dock unpin <id>`, `dock activate <id>`, `dock menu <id>`,
`dock choose <id> <item>`, `dock quit <id>`. An id is the one the dock
files the app under, or one a window of it goes by.
`dock status` is also `debug dump`'s `dock`. Its `scale` is the scale of
the output the dock is on, the live bar's, which its icons are asked for
and drawn at; the live bar moves between outputs with no output changing,
so the scale is read off the output each time.

## 5. Keyboard

**Menu commands in the launcher.** `menu summon appmenu` opens the launcher
on a Menu route listing every command of the focused Mac app: the title,
its path in the meta ink (`File › Export`), its shortcut in keycaps, a
tick where it is checked, disabled commands dimmed and not runnable.
Typing filters, Return runs. This is the Mac's Help search with the
keyboard first; the include binds it to `SUPER + ALT + M`. From the root
query the same commands rank under apps while a Mac app has focus, so
`Space`, a few letters, Return runs one without the route.

**Dock actions in the launcher.** An app row's column (Tab) gains: Quit
(running), the app's dock menu items (running, with a quicklist), Keep in
Dock or Remove from Dock, and for a Mac app Uninstall. Show its windows and
the desktop actions are already there.

**Key equivalents.** Atoll performs a key equivalent itself when the key
reaches the app, and its keys stay where the Mac's are: SUPER is Command
(the Cmd-position key), Ctrl is Control (Ctrl+C still interrupts in a
terminal app, Ctrl+A and Ctrl+E still move in a text field), Alt is Option.
The collision is the window manager's: Hyprland takes a bound SUPER chord
before any window sees it, and the owner binds SUPER with Q, C, V, Z, F, O,
S and more. The shell settles it per focus, with a Hyprland submap.

*The `mac` submap.* While the focused window is a Mac window the shell
switches Hyprland to the submap `mac`, and back to the default when focus
leaves (the compositor's own focus, so an open launcher or panel is under
the default map). The submap holds a copy of every bind of the default map
except the SUPER chords handed to apps, so inside it those chords are
unbound and reach the app as Command.

A bind is handed to apps when its modifiers are SUPER alone or SUPER with
SHIFT, the two layers Mac key equivalents live on, and it is on a key, not
a mouse button, the wheel or a switch. Everything else is copied: SUPER
with CTRL or ALT (the shell's chords, which no Mac app uses), ALT+Tab,
Print, the media and brightness keys, SUPER with a mouse button. A handed
chord stays with the window manager when it is reserved.

`macApps.reservedBinds` in settings.json is the reserved list, chords
written as in `hl.bind` (`"SUPER + H"`), case and spacing ignored, a digit
matching its `code:` form. The default:

| Reserved | For |
| --- | --- |
| `SUPER + H/J/K/L`, with SHIFT | focus and move |
| `SUPER + 1..9`, with SHIFT | workspaces |
| `SUPER + Space` | the launcher |
| `SUPER + Escape` | the system menu |

So SUPER with C, V, X, Z, A, S, F, O, N, T, W, Q, comma and the rest reach
the app: SUPER+Q quits it (the intent of the close bind it displaces) and
SUPER+W closes its window or tab. Taking a chord out of the list hands it
to apps; adding one keeps it for the window manager.

*Generated, not hardcoded.* Hyprland's Lua has no call that lists the
binds with their actions, and `hyprctl binds` names a Lua bind's action
only by an internal number. So the shell's include
(`docs/examples/hyprland/formalshell.lua`) records each bind as the config
makes it: its first lines wrap `hl.bind`, `hl.unbind` and
`hl.define_submap`, and every default-map bind made after them lands in a
table with its chord, action and options. `formalshell_mac_keys(reserved)`
builds the submap from that table and the reserved list, replacing the one
before, and answers how many binds the table holds;
`formalshell_mac_focus(on, window)` says whether the window the shell
found in front is a Mac window, and is dropped when another window is in
front by the time it arrives, so a native window is never taken for the
Mac one focus just left. The include holds the submap over that one window and the default
map over any other, leaving a submap of the user's own alone, and follows
Hyprland's own `window.active` and `window.close` to do it: the map is
right when focus moves with no shell to say so (the shell has exited, or a
window took focus and gave it back between two of the shell's looks), so a
chord is never left dead waiting on the shell. The shell calls the first
when a Mac window first has focus, after a config reload and when the
reserved list changes, and the second on its first look at the compositor,
after each reload and whenever the Mac window in front changes: a shell
started over a session an earlier one left in the submap asks it out. A
reload runs the include in a new Lua state and drops every bind while the
session stays in the submap it was in, so the include leaves `mac` as it
loads: with no shell to build the submap again the default map is the one
in force, and a running shell builds it and asks again. Each
is called only when the config defined it, so a config without the
include logs nothing. A bind the config makes before the include is not
recorded and does nothing over a Mac window; `appmenu status` reads the
count as `macBinds`. The shell's own chords in the include (`fs_bind`)
are binds like any other, so the reserved ones are copied and keep
working. A config must load the include before its binds; one that
inlines its own copy of the include (the owner's) carries the same block
at its top.

*Displaced actions* (float, fit into view, zen, the overview, close) stay
on the keyboard while a Mac app has focus: the launcher lists the window
actions and the shell's toggles, and its keybinds route (`SUPER + K`,
reserved) lists every bind with what it does.

*What the user sees.* The shortcut column of a menu card and of the
launcher's menu rows draws the keys the user presses: the Super glyph for
Command, Ctrl for Control, Alt for Option. Atoll's dbusmenu `shortcut`
already names host keys.

## 6. Launcher entries

Atoll's desktop entries carry `StartupWMClass`, `MimeType` and
`X-Atoll-BundleId` (atoll's contracts.md). An entry with
`X-Atoll-BundleId` is a Mac app's. The shell:

- reads `X-Atoll-BundleId` and `MimeType` in the entry scan
  (`services/appicon.rs`) onto the launcher's `DesktopEntry`;
- trails a Mac app's row with `Mac`, ahead of its window count
  (`Mac · 1 window`);
- matches Mac windows by `StartupWMClass`, which is the bundle id and the
  window's class: `launch::match_windows` takes that tier first, so Enter
  on the row focuses the running app and its window count is its own;
- lists in a Mac app's column (Tab) **Keep in Dock** or **Remove from
  Dock** (`dock pin`, `dock unpin`), and while it runs **Quit <name>**
  (`dock quit`, the app's own Quit item) and the items of its own dock
  menu, read when the column opens and joined under its actions as the
  app answers (`dock choose <id> <item>`). Under `dock.show` `always`
  every app's column has the dock's two; under `never` none has;
- offers **Uninstall** last for a Mac app no fspec package holds: the
  first Enter arms it, the second runs `atoll uninstall <bundle id>` with
  the atoll the entry's `Exec` names (`services/atoll.rs`). Activity shows
  it as an `atoll` item, `Uninstalling <name>`, ending `Uninstalled
  <name>` or failed with atoll's last line. Where fspec is installed the
  action waits for `fspec app owner` to say the spec does not hold the
  app, and fspec's own Uninstall stands where it does;
- orders a file's **Open with** targets: the apps whose `MimeType` holds
  the file's type or a type above it, by name, then a note, `Other apps`,
  then the rest by name. The type is the file's name against
  shared-mime-info's `globs2`, climbed through `subclasses`
  (`crates/fs-menu/src/mime.rs`), read in the menu service when the
  file's column opens. A Mac app trails `Mac` there too;
- shows no launch for a Mac app that is already running: a Mac app is one
  instance, and what a second launch hands it may land in a window it
  already has, so there is none to wait on.

Recent documents per app are a follow-up (6).

## 7. Legs

Each lands with its code and its `dev/smoke-map.toml` lines.

- `--mac-menu`: `dev/mac-stub.py` is a Wayland client that maps a window
  tagged `atoll` and, from the same process, registers a dbusmenu with the
  shell's registrar; its `--log` is the evidence. Real pointer: the titles
  appear when its window takes focus and go when a foot window does; a
  click on File opens its card and a click on New reaches the stub as
  `Event(21, clicked)`; a click on Export opens the submenu in place and
  one on PDF under it reaches the stub; a click on Show Ruler comes back
  checked; the row the stub adds on `AboutToShow` lands in the open card;
  the pointer moved onto Edit's title with Window's card up swaps the card
  with no click, and a click on that title shuts it; the stub never loses
  the keyboard while its menus are up. Then `menu summon appmenu`, real
  keys typing part of an item's name, Return reaching the stub while the
  launcher holds the keyboard; the root query finding a command with the
  stub in front and none with a foot window in front. Under `--sidebar`
  the same on the column's card, plus the rail's menu button.
- `--mac-keys`: the include's recorder and five binds in a real Hyprland,
  real keys from wtype: SUPER + C and SUPER + Q reach the stub and the
  window manager's binds on them do not fire, CTRL + C reaches it with
  Control alone, SUPER + L moves focus out without the stub seeing a key,
  SUPER + CTRL + P still fires, the default map is back over a foot
  window, and a rewritten `macApps.reservedBinds` is followed.
- `--mac-faults`: the same config, and a launcher that starts the shell
  again when asked. `hyprctl reload` with the stub in front: the session is
  in `mac` again, the submap rebuilt, SUPER + CTRL + P firing and

  `mac` while the stub has focus, the default map and a firing SUPER + C

  the shell still gone: the default map, SUPER + L and SUPER + C firing,

  `mac` over the foot window by hand and the shell started: the default
  map, then `mac` and the menu over the stub. The stub stopped (SIGSTOP)

  stub's menu held within a call's wait. The shell ended and the last Mac
  window closed: the default map with no window left.
- `--dock-density`: a second output at twice the scale, focused: `dock
  status` reads its scale and holds the stub's icon at it, and both follow
  focus back.
- `--dock`: no `formalshell:dock` layer with a foot window alone; with the
  stub up, the strip alone; a real pointer parked on the bottom edge

## 8. Follow-ups, in order

1. Window buttons: Mac windows keep their traffic lights on the left while
   native windows have none under Hyprland; decide whether the shell says
   so anywhere (it draws no window buttons itself).
2. The reserved binds as rows in settings (Keyboard page): today the
   list is settings.json's `macApps.reservedBinds` alone.
3. About and Quit: `orderFrontStandardAboutPanel:` is absent in atoll, so
   About does nothing; Quit through the app menu is covered above.
4. Status items (`NSStatusItem`) as StatusNotifierItems over the same
   dbusmenu server, landing in the shell's tray with no shell change.
5. The Mac window shadow drawn by the shell (atoll spec 4.4).
6. Recent documents per app (`NSDocumentController`'s list exported in the
   dock menu, and as launcher rows).
7. Electron apps in Mac mode (atoll spec 12, atoll branch `electron-mac`)
   register through the same two interfaces from the Electron main
   process, whose pid is its windows'. Their windows carry Electron's
   app_id (Notion's is `notion`) and no `atoll` tag, so the shell's test
   for a Mac window, the tag alone today, has to take a window whose
   desktop entry carries `X-Atoll-BundleId` as one too (the entry found by
   `StartupWMClass`), for the strip, the `mac` submap and the dock.
8. An in-window menu bar in atoll for desktops with no registrar.
9. A sidebar too short for every title: the Menu card keeps its first row
   and that row opens the whole menu.
10. A file opened in a running Mac app from Open with. The shell runs the
    entry's `Exec` on the file; atoll has to hand it to the running
    instance (its branch `url-forward`) and CotEditor's document has to
    open (`-[NSDocument objectSpecifier]`, atoll's coteditor-4 stream).
    With both in, `--mac-app` can press Return on the target and wait on
    the file's window.
11. A Mac window in a tile keeps its own first size for its first seconds
    (CotEditor 800 wide in a 960 tile): atoll's answer to the tile's first
    configure.
