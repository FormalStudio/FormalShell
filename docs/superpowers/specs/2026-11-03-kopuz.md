# Kopuz integration

The owner plays music in Kopuz and FormalMusic, both frontends of `kopuzd`.
MPRIS carries only title, artist, album, length and art for them, so the shell
cannot reach what Kopuz knows: the lyrics it already resolved (server lyrics,
embedded tags, its own providers), whether the track is a favourite, and the
rating, save and follow actions a streaming source offers. This spec has the
shell talk to `kopuzd` directly, with no Kopuz crate linked and nothing
installed when Kopuz is absent.

## Transport

`kopuzd` serves gRPC (`kopuz.v1.Kopuz`, `kopuz/crates/proto/proto/kopuz.proto`)
over a Unix socket at `$XDG_RUNTIME_DIR/kopuz/kopuzd.sock`, falling back to
`$XDG_CACHE_HOME/kopuz/kopuzd.sock` (kopuz `client::default_socket_path`). The
socket's 0600 mode is its access control; there is no auth.

A new pure crate, `crates/fs-kopuz`, holds the wire code, written by hand:

- Protobuf: varint and length-delimited encode and decode for the handful of
  messages below, field numbers copied from `kopuz.proto` with the proto's
  line cited in a comment. Unknown fields are skipped, so a newer daemon still
  reads.
- HTTP/2 with prior knowledge (cleartext, no TLS, no upgrade): the preface,
  SETTINGS and its ack, one HEADERS block per call encoded with HPACK literals
  only (no Huffman, no table), DATA frames carrying gRPC's 5-byte prefix,
  WINDOW_UPDATE for every DATA received so the event stream never stalls,
  PING answered, GOAWAY and RST_STREAM ending the call. Response header blocks
  are skipped, never decoded: a call succeeds when it ends with a message and
  fails otherwise (the `grpc-status` text is not needed to fall back).
- No tokio, no `h2`, no `prost`, no `tonic`. The service side runs on the
  shell's own async-io executor like every other service.

The crate's tests cover the codec against bytes captured from `prost` for the
same messages, and a frame-level exchange against an in-test server (an
`h2`+`tokio` dev-dependency is fine; it never ships).

## What the shell reads and calls

| RPC | Use |
| --- | --- |
| `GetPlayerState` | the playing `TrackInfo` (`row`, field 14): its `key`, title, artist |
| `Subscribe` | `Event.player_state` (1) to follow track changes and favourite changes without polling; `library_invalidated` (6) for favourites |
| `GetLyrics(TrackRef{key})` | `Lyrics.synced` (2) to `fs_media::lyrics::Line`; `plain` (1) is kept for a later plain view and not drawn |
| `GetFavorites` | the favourite refs, to know whether the playing key is one |
| `SetFavorite{key, favorite}` | the like toggle for a library track |
| `Rate{item_ref, rating}` | like or dislike where the source gives a `CatalogActions.rate_ref` (YouTube Music) |
| `DontRecommend{key}` | the "not this" action where the source supports it |

Which of like (favourite), rate and don't-recommend a track offers follows the
Kopuz GUI's own now-playing controls (`kopuz/crates/components/src/playback/controls.rs`,
`kopuz/crates/hooks/src/favorites.rs`): read them before building the action
list, and show only what Kopuz itself would show for that track.

## Which player is Kopuz

The MPRIS player whose bus name is `org.mpris.MediaPlayer2.kopuz` or
`org.mpris.MediaPlayer2.kopuz.instance<pid>` is Kopuz. The service connects
while such a player exists and the socket is there, and drops the connection
when it goes. Its title and artist are checked against the daemon's `row`
before anything is attributed to it; a mismatch (the GUI and a remote daemon)
means no integration for that track, never a wrong heart.

## Surfaces

- Lyrics: when the active player is Kopuz and `GetLyrics` returns synced
  lines, they win over every web provider and are cached like a hit with
  source `kopuz`. An empty answer falls through to the existing chain.
- Media panel: a heart beside the transport controls, filled when the playing
  track is a favourite (or rated like), only while the active player is Kopuz
  and the daemon answers. A dislike or don't-recommend action sits in the same
  row only when Kopuz would offer it. Keyboard reachable like every panel row.
- IPC: `media like [toggle|on|off]`, `media dislike`, and the kopuz block in
  `media status` (`kopuz: {connected, key, favorite, actions}`); the golden
  file gains these lines.
- Nothing appears for any other player, and with no daemon the panel is
  exactly what it is today (honest absence, not a disabled heart).

## Out of scope

Queue, library browsing, search, playlists and radio stay in Kopuz. A plain
(untimed) lyrics view is its own change.
